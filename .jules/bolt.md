## 2025-03-09 - [Bulk position updates in useStore.ts]
**Learning:** Bulk state updates for scene and quest stage positions (`updateScenesPositions` and `updateQuestStagesPositions`) used an O(N * U) nested Array.prototype.find() loop within map(). This causes noticeable lagging and high CPU overhead as nodes or updates scale up. By preprocessing the `updates` array into an O(1) Map first, performance is optimized to O(N + U). To preserve exact semantic equivalence of Array.prototype.find(), we must only store the first occurrence of each key in the Map (i.e. `if (!map.has(key)) map.set(...)`).
**Action:** Always check array searches inside nested map/filter loops and refactor them to use Maps for O(1) lookups. Explicitly check for duplicate keys to maintain exact semantic alignment with `find()`.
