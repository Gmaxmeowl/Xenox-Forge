## 2025-05-15 - [Algorithmic Graph Optimization & Granular Selectors]
**Learning:** In complex graph editors like GraphView and QuestEditor, the bottleneck often lies in $O(N^2)$ edge resolution logic within the render loop and $O(N \cdot U)$ bulk state updates. Replacing array `.find()` with memoized `Map` lookups reduced edge resolution time by ~26x (1400ms to 53ms for 1000 nodes). Additionally, using a "catch-all" Zustand selector `const state = useStore()` causes the entire component to re-render on every state change, which is catastrophic for complex editors.
**Action:** Always prefer granular selectors for Zustand state and use memoized `Map` lookups for resolving relationships/edges in graph-based UIs. Use Map-based bulk updates in the store for $O(N+U)$ complexity instead of $O(N \cdot U)$.
