## 2026-10-27 - [Optimize Bulk Position Updates with Map Lookups in Store]
**Learning:** In Zustand actions such as `updateScenesPositions` and `updateQuestStagesPositions`, updates are passed as an array of `{ id, position }` updates. When mapping across large item collections (`scenes` or `stages`), calling `updates.find(u => u.id === item.id)` leads to $O(N \times U)$ quadratic complexity on every mouse move during node dragging, creating significant frame drops. Furthermore, when converting to a `Map`, checking truthiness of `map.get(key)` can introduce subtle bugs if coordinates are 0 (falsy), so explicit `map.has(key)` checks must be used.
**Action:** Pre-index the `updates` array into a `Map<string, Point>` before mapping over collections, storing the first occurrence of each key to maintain exact equivalence with `find()`, and checking `map.has(item.id)` to safely retrieve updated positions in $O(N + U)$ time.
